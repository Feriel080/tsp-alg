# TSP Algorithm Project

This project is a small Python implementation of the Traveling Salesman Problem (TSP) for a set of randomly generated villages. It compares two solution strategies:

- A greedy nearest-neighbor construction heuristic
- A local search optimization step that improves the route by swapping villages

The objective is to find a valid round-trip route that visits every village exactly once and returns to the starting point while minimizing total travel distance.

## Project overview

The project includes:

- `helping_func.py`: utility functions for village generation, Euclidean distance computation, matrix building, route length calculation, and validation of feasibility
- `greedy_alg.py`: greedy TSP solver class
- `local_search.py`: local search optimization class
- `main.py`: experiment runner that evaluates several problem sizes and saves the results to a CSV file
- `results/`: output directory for performance metrics
- `tests.py`: small script for quick checks and experiments

## How it works

1. Random villages are generated as 2D coordinates.
2. A distance matrix is computed between all villages.
3. The greedy algorithm picks the closest unvisited village from the current one until all villages are included.
4. The route is closed by returning to the starting village.
5. A local search phase explores swap-based improvements and keeps only beneficial changes.
6. Results are logged in `results/results.csv`.

## Requirements

This project needs Python 3 and the following packages:

- numpy
- matplotlib
- colorama

You can install them with:

```bash
pip install -r requirements.txt
```

## Run the project

From the repository root:

```bash
python main.py
```

This script runs the optimization for several village counts (`10`, `20`, `50`, and `100`) and stores the comparison metrics in:

```bash
results/results.csv
```

## Example output

The CSV includes columns such as:

- `Nbr_ville`
- `Longueur_glouton`
- `t_glouton`
- `Longueur_LS`
- `t_LS`
- `Gain`

These values compare the initial greedy route to the improved local search route.

## Notes

- The route is considered valid only if it contains every village exactly once and returns to the start.
- The algorithm is designed for experimentation and educational purposes rather than production-grade TSP optimization.
- Visualization files generated by the route-drawing code are stored in the algorithm-specific output folders.
